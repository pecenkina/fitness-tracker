# Требования к веб-приложению «Персональный фитнес-трекер»

## Общие требования

1. Приложение должно иметь интуитивно понятный интерфейс, адаптивный дизайн и корректно работать на компьютерах и мобильных устройствах.
2. Приложение должно работать как адаптивный веб-сайт в современных браузерах на компьютерах, планшетах и смартфонах.
3. Приложение должно предоставлять авторизацию пользователей по email и паролю; возможность входа через внешние сервисы планируется для следующей версии.
4. Данные тренировок, профиля и планов должны сохраняться в базе данных и быть доступны только соответствующему пользователю.
5. Основные функции учёта тренировок должны работать без подключения фитнес-браслета.

## Функциональные требования

1. Главная страница должна содержать дашборд с графиками и аналитикой:
   - Прогрессия рабочих весов по упражнениям.
   - Изменение максимальных весов по выбранному упражнению.
   - Рейтинг до 20 упражнений по максимальному зарегистрированному весу.
   - Распределение нагрузки на мышечные группы и части тела.
   - Количество тренировок, их продолжительность и тренировочный объём.
   - Выбор периода анализа: неделя, месяц, год или произвольный интервал.
   - При наличии измерений — шаги, калории, пульс, насыщение крови кислородом (SpO₂) и время активности.

2. На главной странице должны быть доступны основные действия:
   - Добавление новой тренировки.
   - Переход в профиль пользователя.
   - Переход в раздел рекомендаций.
   - Переход к журналу тренировок.

3. Журнал тренировок должен позволять:
   - Просматривать прошедшие тренировки по датам.
   - Открывать подробную информацию о тренировке.
   - Добавлять, изменять и удалять записи.
   - Указывать упражнения, подходы, повторения, рабочие веса, дату и продолжительность.
   - Просматривать историю результатов по отдельным упражнениям.

4. Приложение должно поддерживать составление тренировок:
   - Добавление упражнений и подходов вручную.
   - Создание, редактирование и сохранение тренировочных планов.
   - Запуск тренировки из сохранённого плана.
   - Отдельное хранение фактически выполненной тренировки и шаблона плана.

5. Приложение должно содержать локальный каталог упражнений:
   - Название, описание, целевые мышечные группы.
   - Уровень сложности и необходимое оборудование.
   - Поиск и фильтрация по названию, мышцам, сложности и оборудованию.
   - Возможность наполнения или обновления каталога из внешнего API.

6. Страница рекомендаций должна:
   - Предлагать упражнения из каталога в зависимости от цели пользователя.
   - Поддерживать подбор по мышечным группам и сложности.
   - Позволять добавлять выбранные упражнения в тренировочный план.

7. Страница профиля должна:
   - Отображать и позволять изменять основные сведения о пользователе: рост, вес, возраст или дату рождения, пол, тренировочную цель.
   - Предоставлять изменение параметров учётной записи.
   - Предусматривать раздел подключения внешних фитнес-сервисов.

8. Аналитика должна:
   - Пересчитываться после изменения или удаления тренировки.
   - Отображать доступные данные без подмены отсутствующих измерений нулевыми значениями.
   - Применять понятные правила вычисления тренировочного объёма и распределения нагрузки.

## Дополнительные функциональные требования (необязательно для MVP)

1. Подключение нескольких фитнес-сервисов через отдельные API-адаптеры:
   - Синхронизация доступных данных о шагах, пульсе, калориях, SpO₂ и активности.
   - Отображение статуса подключения и времени последней синхронизации.
   - Исключение дублирования измерений из разных источников.
   - Доступность конкретной интеграции зависит от API провайдера.

2. Авторизация через внешних провайдеров с использованием OAuth/OIDC.
3. Расширенная аналитика активности, восстановления и сравнение периодов.
4. Интеграция с FatSecret для последующего учёта питания и пищевой ценности.
5. Расширенные персональные рекомендации на основе истории тренировок.

## Критерии приёмки MVP

1. Пользователь может зарегистрироваться, войти и заполнить профиль.
2. Пользователь может найти упражнение по названию и фильтрам.
3. Пользователь может создать тренировку вручную и запустить тренировку из плана.
4. Завершённая тренировка отображается в журнале; её можно изменить и удалить.
5. Графики прогрессии весов и нагрузки обновляются по сохранённым данным.
6. Данные разных пользователей изолированы.
7. Интерфейс корректно отображается и работает в браузерах на компьютерах и мобильных устройствах.
8. Основные функции доступны без браслета; отсутствие данных внешних сервисов корректно отображается.
