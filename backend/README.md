# Локальный запуск Fitness API

Нужны Node.js 22 или новее, npm, PostgreSQL и psql. Из папки backend на машине с локальной базой под текущей ролью PostgreSQL выполните:

```sh
createdb fitness_tracker_dev
psql -v ON_ERROR_STOP=1 -d fitness_tracker_dev -f migrations/001_initial.sql
psql -v ON_ERROR_STOP=1 -d fitness_tracker_dev -f migrations/002_catalog_ru.sql
npm ci
```

Для запуска задайте переменную PGDATABASE со значением fitness_tracker_dev. При необходимости укажите PGUSER, PGHOST, PGPASSWORD и PGPORT для подключения. Вместо них можно передать строку подключения через DATABASE_URL. Пароли задаются в окружении процесса.

В PowerShell для локального PostgreSQL:

```powershell
$env:PGDATABASE = "fitness_tracker_dev"
$env:PGUSER = "postgres"
npm start
```

В Bash:

```sh
PGDATABASE=fitness_tracker_dev npm start
```

Откройте в браузере:

- http://127.0.0.1:3000/api/health — проверка подключения к базе.
- http://127.0.0.1:3000/api/exercises — каталог из PostgreSQL. Фильтры q, equipment, muscle_id, goal и difficulty можно сочетать. В поиске по названию «е» и «ё» равнозначны.
- http://127.0.0.1:3000/api/exercises?q=жим — поиск по названию. Для полной карточки добавьте числовой id результата к пути /api/exercises/.
- http://127.0.0.1:3000/api/exercisedb/EIeI8Vf — внешняя карточка с русским переводом. Требуется доступ к ExerciseDB. Ответ содержит источник для атрибуции в интерфейсе.

Миграция 001 создаёт схему на пустой базе. Миграция 002 добавляет пять авторских русских записей. Поиск работает локально. Внешние карточки запрашиваются по строковому идентификатору поставщика, их ответы не записываются в PostgreSQL. Для записей тренировок используется числовой id локального упражнения.

## Журнал тренировок на локальном компьютере

На новой базе выполните миграции 001–007 по порядку. При обновлении с версии со 100 упражнениями выполните один раз `backend/migrations/007_accounts_and_sharing.sql` в SQL-редакторе DBeaver для базы fitness_tracker_dev. После этого из корня проекта в PowerShell выполните:

```powershell
npm ci --prefix frontend
npm run build --prefix frontend
npm ci --prefix backend
$env:PGDATABASE = "fitness_tracker_dev"
$env:PGUSER = "postgres"
npm run journal --prefix backend
```

Используйте те же параметры подключения, с которыми работает API. Если старый сервер занимает порт 3000, завершите его через Ctrl+C в его терминале. Откройте http://127.0.0.1:3000/ . При последующих запусках достаточно команды запуска с настроенным подключением.

Зарегистрируйтесь по электронной почте. В профиле кнопка «Сменить аккаунт» открывает список аккаунтов устройства. Кнопка «Выйти» завершает сессию выбранного аккаунта. Для переноса прежних тренировок, планов и параметров профиля администратор после регистрации владельца один раз выполняет из корня проекта с теми же параметрами подключения:

```powershell
node backend/adopt-local-journal.mjs "мой-адрес@example.org"
```

Чтобы назначить модератора, после регистрации его аккаунта выполните в DBeaver, подставив нужную почту:

```sql
UPDATE users SET moderator = true WHERE lower(email) = lower('moderator@example.org') RETURNING email;
```

После обновления страницы в разделе «Упражнения» у модератора появится очередь. Одобрение публикует карточку с отметкой «Пользовательское». Старые пользовательские карточки остаются в каталоге.

В журнале раскройте запись и нажмите «Поделиться тренировкой». Получатель открывает ссылку и при необходимости входит в аккаунт. Копия появляется в календаре на сегодня с исходными подходами и пустыми отметками выполнения. Повторное открытие той же ссылки тем же аккаунтом не создаёт дубль. Чтобы проверить на одном ПК, откройте ссылку в другом профиле браузера или после переключения аккаунта.

Для обмена между устройствами открывайте приложение по общему адресу сервера. По умолчанию используется 127.0.0.1. Для проверки в своей сети можно перед запуском задать в PowerShell `$env:HOST = "192.168.1.10"` (подставьте адрес компьютера) и открыть сайт по этому адресу на обоих устройствах. Для общего HTTPS-сайта за обратным прокси задайте `$env:COOKIE_SECURE = "true"` и используйте внешний адрес сайта.

В форме можно добавить упражнения из базы, для каждого записать несколько подходов с разными весами и повторениями. Для собственного веса укажите 0 кг. Пустое поле веса сохраняется как неизвестное значение. После сохранения тренировка раскрывается в истории.

Главная страница «Обзор» показывает статистику за текущий календарный месяц по дате тренировки. Объём — сумма повторов, умноженных на вес каждого подхода. Подходы без указанного веса не участвуют в расчёте. При нескольких целевых мышцах объём упражнения делится между ними поровну. Блок последних тренировок показывает три последние записи за всё время.

Чтобы исправить запись, откройте «Журнал тренировок», раскройте тренировку и нажмите «Изменить». Сохранение заменяет упражнения и подходы одной транзакцией (PUT /api/local/workouts/:id). Кнопка «Удалить» запрашивает подтверждение и удаляет тренировку с подходами (DELETE /api/local/workouts/:id).

### Обновление журнала и календаря

Если миграции 001 и 002 уже применены, выполните в базе fitness_tracker_dev файл migrations/003_exercise_completion.sql. Миграцию 003 можно запускать повторно. Существующие упражнения в записях отмечаются как выполненные.

Раздел «Упражнения» позволяет отправить своё упражнение на модерацию. В форме тренировки доступны сохранение только плана и одновременное сохранение тренировки с шаблоном. На экране «Мои планы» можно редактировать название, упражнения и подходы. Календарь хранит запланированное занятие отдельно от шаблона. Для записи результата выберите день, нажмите «Отметить выполнение» и поставьте галочки у выполненных упражнений. Пропущенные упражнения остаются в журнале и исключаются из расчётов весов, объёма и нагрузки.

После миграции 003 примените migrations/004_set_completion.sql в fitness_tracker_dev.
Она переносит прежнюю отметку упражнения на каждый его подход. Повторный запуск сохраняет индивидуальные отметки.
В форме записи колонка «Готово» отмечает отдельный подход. Журнал сохраняет пропущенные строки,
а статистика учитывает вес и повторы только выполненных подходов.

Для расширения русского каталога выполните migrations/005_expand_catalog_ru.sql после предыдущих миграций. На базе с пятью начальными упражнениями каталог будет содержать 45 встроенных упражнений. Собственные записи пользователя сохраняются. Оборудование и мышцы из новых карточек автоматически появляются в фильтрах и форме создания упражнения.

После миграции 005 выполните migrations/006_catalog_100_ru.sql в fitness_tracker_dev. Она добавляет ещё 55 упражнений, включая упражнения в силовых и блочных тренажёрах. Встроенный каталог будет содержать 100 упражнений.
